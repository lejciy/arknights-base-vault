## 记录格式

```markdown
## Dxx — 标题（YYYY-MM-DD）

- 决定：

```

详细历史裁决目前保留在 `meta/内容目录与进度.md` 的原始记录中；后续新增裁决统一登记于本文。

## D12 — 干净语料目标与模块 README 去维护化（2026-09-10）

- 问题：模块1、模块2 的 README 把本地同步记录、变更纪事和「已知问题」写进了 `docs/`，而这些文档带 `status: canonical`、进 RAG，会把仓库维护过程当成玩家知识检索出来；同样内容在 `meta/内容目录与进度.md` 已有登记，构成重复真源。
- 决定：在《知识库模块设计》确立「干净语料库」目标——`docs/` 只保留当前有效的玩法知识，维护内容（同步/导入记录、变更纪事、已知问题、进度、待补、素材台账、写作规范、本地路径）一律只登记在 `meta/`。模块 README 降为 `type: index` 导航入口，只写职责与分区导航。
- 影响：`docs/1-基础设定/README.md`、`docs/2-干员技能/README.md` 已清理，被删段落的内容基本已在 `meta/内容目录与进度.md` 登记，仅「跑单/囤单建载体」一项补登为该文遗留待办 7，无信息丢失；同时清除了模块1 正文里「某日重订/整合素材 docx」式批注，并修掉 README 对不存在文件 `数据源.md` 的悬挂引用。root README 与 `meta/协作与引用规范.md` 同步声明该边界；模块3–7 README 的同类「现状/待补/素材出处」段落按同一规则逐步下沉。
