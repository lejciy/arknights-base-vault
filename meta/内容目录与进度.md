## 2. 模块定义与现状对照

### 2.1 模块1：基础设定层

**职责**：提供所有运算和决策的底层物理规则与事实框架。

**包含**：
- 游戏基础机制（心情消耗公式、生产率计算逻辑、设施加成规则等，参考 PRTS.wiki 基准）
- 基建空间与设施定义（各设施类型、等级面板、电力等设施属性；布局架构定义划归模块7）
- 基础资源体系（物流主链、资源用量常数；全局资源注册划归模块3——2026-09-08 裁决，其生产/消费两端均为组合知识）

**不包含**：版本迭代带来的干员新增或用户需求变化（属于模块2更新和外部输入）。

**性质**：几乎长期保持不变，若未来基建玩法改版则整体调整。

**内部分区**（2026-09-08 拆分，导航见 `docs/1-基础设定/README.md`）：

## 4. 模块间依赖关系总览

```
模块1 事实层（机制/设施/资源）
   ├──> 模块3 组合层 ──引用──> 模块2 干员技能层（单向：3 引用 2，2 不持有组合归属）

   ├──> 模块5 操作层 <──模块6 引用手法名称
   ├──> 模块7 布局层（查表＋选择推荐，引用模块1 的设施事实）
   └──> 模块6 决策层（顶层调参层，可引用 1/3/4/5/7 做综合判断与解释）

运行时输入（资源目标/基建布局/用户偏好）
   └──由 Agent 通过对话采集，与知识库内容（尤其模块5/6/7）推理时动态组合生成方案
```

- **事实层**：模块1 被模块3、4、5、6、7 引用。
- **组合层**：模块3 单向引用模块2。
- **执行层**：模块6 引用模块5 的手法名称；模块4 与模块6 按问题类型分工。
- **布局层**：模块7 承载布局查表与按需求选择推荐，被模块3（引用布局名）与模块6（场景决策）引用，自身引用模块1。
- **决策层**：模块6 作为顶层调参层。
- **运行时输入**：知识库内不做固定配对绑定。
