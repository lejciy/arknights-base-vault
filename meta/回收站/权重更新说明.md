# 回收站产物权重更新

## 数据路径

上游为 [Kengxxiao/ArknightsGameData](https://github.com/Kengxxiao/ArknightsGameData) 的国服 `zh_CN/gamedata/excel/`：

- `building_data.json`：奖池生效区间、特殊池关联、积分阈值、条目权重、数量、积分增量及设施参数。
- `item_table.json`：按材料 ID 匹配中文名与品级。

两份文件固定在同一 commit。上游的 `master` 仅用于发现版本，保存时记录解析后的完整 SHA 与两份文件的 SHA-256。[原始解包 JSON](new_recycle_data.json) 保持不变；[产物配置](产物配置.json) 为当前接受的规范化快照，正文末尾附录为其派生表。

脚本：[update-recycle-data.py](../../scripts/update-recycle-data.py)，仅依赖 Python 标准库。默认只读；`--write` 写入快照、正文附录与正文 `updated` 日期。正文的其他段落保持人工维护。

## 更新步骤

在仓库根目录执行；以下 `python` 指向可用 Python 3。

1. 查询上游并比较。省略 `--ref` 时，从建筑文件最近一次提交解析完整 commit，再以该 commit 读取两份文件。

   ```powershell
   python scripts/update-recycle-data.py --fetch --as-of '2026-10-13T12:00:00+08:00'
   ```

2. 使用查询得到的 commit 固定本次更新；把时点改成需要更新的北京时间。

   ```powershell
   python scripts/update-recycle-data.py --fetch --ref 17759cc8cdf37388414145d16262a3a06f3ab25e --as-of '2026-10-13T12:00:00+08:00' --write
   ```

3. 检查快照与附录差异，重新生成标题和消歧索引。

   ```powershell
   git diff -- 'meta/回收站/产物配置.json' 'docs/1-基础设定/设施与进驻/回收站机制.md'
   node scripts/build-agent-index.mjs
   ```

联网读取经 GitHub Contents API，使用 `Accept: application/vnd.github.raw+json`，不依赖 raw 域名。已下载的数据也可离线核对，文件须来自同一 commit：

```powershell
python scripts/update-recycle-data.py --building-data '<building_data.json路径>' --item-table '<item_table.json路径>' --commit '<完整40位SHA>' --as-of '2026-10-13T12:00:00+08:00'
```

加 `--write` 才落盘。本地模式记录文件摘要与提供的 SHA，文件是否确属该 commit 由下载过程保证；联网模式直接按固定 SHA 取文件。

重新校验当前附录或用原始资料复算：

```powershell
python scripts/update-recycle-data.py --as-of '2026-10-13T12:00:00+08:00'
python scripts/update-recycle-data.py --snapshot 'meta/回收站/new_recycle_data.json' --as-of '2026-10-13T12:00:00+08:00'
```

## 生成与校验口径

- 按时间戳选择恰好一个生效普通池，再读取其 `extraPoolId`；时间省略时区按 UTC+8 解析，日期输入取该日 00:00。更新时建议明确提供带时区的完整时间。
- 已接受快照记录 `selected_at`。旧池到期后，比较基线仍取上次生成时的池，新配置按本次时点选池。
- 概率使用每池实际总权重，支持总权重变化；当前的 10000 是数据结果。
- 材料 ID 去重并匹配名称，权重与数量须为正整数，积分增量须为非负整数；缺项、空池、多池重叠与条目结构变化终止生成。
- 合并两池的材料 ID，在一张表中按品级与 ID 排序，分别保留权重、池内概率、普通池积分。数量规则当前为每条目 1 份。
- 权重变化可直接刷新附录。设施效率、投料、等级、解锁、积分阈值、品级/数量/积分规则、既有 `targetTags`、投料材料名称或产物范围变化时，列出机制变化并保留现有正文与快照。
- 材料增删涉及正文的 SS 无限兑换材料口径，需先核对新材料范围；设施或结算参数变化需先校准对应正文。随后按校准结果调整生成/校验口径及接受快照，再继续刷新。脚本保持限定的权重更新职责。
- 每次执行为一次更新检查。运行频率交由维护流程安排，本次未建立定时任务。
