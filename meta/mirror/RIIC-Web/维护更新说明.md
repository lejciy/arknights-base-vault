## 2. 文件清单与字段

### raw（`src/generated/arkntools/`，原样镜像）

| 文件 | 内容 | 关键字段 |
|---|---|---|
| `building-skill-catalog.json` | 技能目录（755 条，键=技能 id） | `name` 中文名、`descriptionRich` 富文本原文、`tags` 标签、`icon` 图标路径 |
| `operator-catalog.json` | 干员目录（429 名，数组） | `id`（char_xxx）、`name`、`order`（数据集内序号 0–428，上游 building.json char 列表原始位置，≈实装先后；RIIC-Web 用于默认倒序展示，本库可作刷新时的新增干员探测基线）、`rarity`（即实际星数）、`profession`/`position`（数值代码）、`portrait`、`buildingSkills[]`（`index` 槽位 / `id` 技能 / `elite` / `level` 解锁条件） |
| `term-catalog.json` | 官方术语表（82 条） | `name`、`desc`（富文本）、`descText`（纯文本） |
| `operator-rarities.json` | 干员 → 星级 | 平铺映射 |
| `source.json` | 上游出处清单 | 源头仓库与 commit、产物图标映射 |

### clean（`clean/`，脚本生成）

| 文件 | 相对 raw 的差异 |
|---|---|
| `building-skill-catalog.json` | `descriptionRich` → `description` 纯文本；删 `icon`；新增 `termRefs`（引用的弹窗词条：`key`/显示 `text`/官方 `name`+`desc` 释义，使条目自包含，见 §2 末） |
| `operator-catalog.json` | 删 `portrait` 与 `position`（近战/远程位属战斗信息，基建用不到；raw 中保留）；新增 `professionLabel` 职业中文名（映射源：RIIC-Web `messages/records/zh.json` 的 `operator_presentation_professions`，1近卫/2狙击/3重装/4医疗/5辅助/6术师/7特种/8先锋）；每个技能槽位新增 `unlock` 中文解锁标签（见 §3），`elite`/`level` 保留 |
| `operator-skill-text.json` | **干员技能全文视图（推荐日常引用）**：每干员一条（含 `professionLabel`），`skills[]` = 技能文本 × 解锁口径合并（`name`/`unlock`/`elite`/`level`/`description`/`tags`/`termRefs`），对应 RIIC-Web 站点技能查询页每列形态，条目自包含 |
| `skill-terms.json` | **词条/类别集中索引**：`terms` 官方术语 82 条；`placeholders` 描述内 `<$cc.xxx>` 占位词条 67 键 → `{texts 显示文字变体, termId 术语回链, usedBy 引用技能}`（如「作业平台」「黑钢国际」）；`tags` 技能标签词汇 44 个 → `{count, skills}`；`rooms` 技能 id 首段前缀 → 设施名 × 技能数（映射源：RIIC-Web `messages/zh.json` 的 `Rooms.*`） |
| `term-catalog.json` | 取 `descText` 为 `desc` |
| `operator-rarities.json` / `source.json` | 原样透传（无标记无图径） |

清洗规则要点：富文本仅两种标记——配对标签 `<@cc.kw|vup|vdown|rem>文字</>` 保留文字，自包含占位符 `<$cc.xxx>` 直接删除（显示文字永远由相邻配对标签携带，含 `<@cc.kw><$key>文字</>` 嵌套形态；个别词条显示文字有变体如「莱茵科技类/莱茵科技类技能」，`skill-terms.json` 以去重列表记录）；term 用上游自带 `descText`。

## 3. 解锁/提升口径（与 RIIC-Web 站点一致）

口径移植自 RIIC-Web 的 `src/operator-presentation.ts` + `src/operatorPortraits.ts`（`isBuildingSkillEnhanced`）+ `messages/helpers/zh/OperatorPresentation.json`（同 commit `a427969`）。站点用语是**「初始解锁」而非「精0解锁」**。

**解锁前缀**（由 `elite`/`level` 决定）：

| raw 值 | 前缀 | 说明 |
|---|---|---|
| elite=0, level=1 | `初始` | 精零即持有 |
| elite=0, level>1 | `等级 {level} ` | 低星干员（当前全量为 level=30） |
| elite≥1, level=1 | `精英 {elite} ` | 精英化后解锁 |
| 其余 | `精英 {elite} · 等级 {level} ` | 当前数据无此组合 |

**解锁/提升后缀**：「提升」判定 = 同干员内按技能 id **最后一个下划线之前的前缀**分组（如 `train_spd&profession_020` → `train_spd&profession`），组内 ≥2 条时**除 index 最小者外均为提升版**。非提升版后缀为「解锁」。

**全量分布**（755 个干员技能槽位，2026-09-08）：

| unlock | 条数 | | unlock | 条数 |
|---|---|---|---|---|
| 初始解锁 | 450 | | 精英 1 解锁 | 78 |
| 精英 2 解锁 | 210 | | 精英 1 提升 | 9 |
| 精英 2 提升 | 157 | | 等级 30 解锁 | 16 |
| 等级 30 提升 | 1 | | （提升版合计 167） | |

**典型形态**：

- 两段链（基础→精2替换）：芙兰卡 `train_spd&profession_020`(初始解锁) → `_021`(精英 2 提升)
- 三段链（精0→精1→精2 逐段替换）：赫拉格 `dorm_rec_all&oneself_010`(初始解锁) → `_011`(精英 1 提升) → `_012`(精英 2 提升)
- 等级链（低星，等级替代精英阶段）：杜林 `dorm_rec_all&oneself_000`(初始解锁) → `_001`(等级 30 提升)
- 独立第二技能（非替换）：阿米娅 `control_tra_spd_000`(初始解锁) + `dorm_rec_all_010`(精英 2 解锁)

**注意**：解锁数据仅含 `elite`/`level`，**无潜能字段**——D9 裁决：基建技能解锁不依赖潜能条件，潜能数据无需引入。

## 4. 刷新流程

1. **取新镜像**：确定 RIIC-Web 新 commit（其 main 上 "chore: 同步 arkntools 干员资源" 类自动提交即为数据刷新点），用 GitHub contents API 整体覆盖 `src/generated/arkntools/`（本机直连 raw.githubusercontent.com 不通，走 API）：

   ```bash
   COMMIT=<新commit>
   for f in building-skill-catalog.json operator-catalog.json operator-rarities.json term-catalog.json source.json; do
     curl -sf --connect-timeout 10 --max-time 120 \
       "https://api.github.com/repos/KnightCodeSquareMatrix/RIIC-Web/contents/src/generated/arkntools/$f?ref=$COMMIT" \
       -H "Accept: application/vnd.github.raw+json" -o "meta/mirror/RIIC-Web/src/generated/arkntools/$f"
   done
   ```

2. **更新出处记录**：改本目录 `README.md` 的 commit 表，并核对 `source.json` 内源头 arkntools commit 是否随动。
3. **重跑清洗**：仓库根执行 `node scripts/clean-riic-skills.mjs`。脚本内置校验会硬失败：技能/干员/术语句数不一致、描述残留标记、全文视图引用了技能目录缺失的技能 id。
4. **核对报告**：条数（当前基线 755/429/82）、解锁口径分布（当前基线见 §3 表）、词条索引（当前基线：占位符 67 全回链/标签 44/设施 9/termRefs 内嵌 142 技能）、描述去除率（当前约 46%）。任一基线变化即上游数据有实质增删，同步更新本文 §1/§3 的数字。
5. **快照重渲染**：仓库根执行 `node scripts/render-skill-snapshot.mjs docs/2-干员技能`（全量、幂等），随后将生成的 `标签速查.md` 移至 `docs/3-组合库/`；`歧义-简称合称.md` 为人工文件，渲染不覆盖。改完用 `git diff` 过目变更；`scripts/verify-skill-snapshot.mjs` 可选做数据级校验（分片与 JSON 真源的槽位/描述一致性）；再检查 `docs/2-干员技能/` 内的 JSON 副本是否需要随 `clean/` 更新。`scripts/sync-skill-snapshot.mjs` 已退役（D16），勿再运行。

## 5. 使用示例

```bash
# 查某干员全部技能（文本+解锁口径）——最常用
node -e "const t=require('./meta/mirror/RIIC-Web/clean/operator-skill-text.json');
  console.log(JSON.stringify(t.find(o=>o.name==='赫拉格'),null,2))"

# 按技能 id 查原文
node -e "console.log(require('./meta/mirror/RIIC-Web/clean/building-skill-catalog.json')['dorm_rec_all&oneself_012'])"

# 查某术语（如 感知信息）的官方定义与提供者
node -e "console.log(require('./meta/mirror/RIIC-Web/clean/term-catalog.json').cc_bd_a1)"

# 查「作业平台」释义与涉及技能（占位词条 → 术语回链 + 引用技能）
node -e "const st=require('./meta/mirror/RIIC-Web/clean/skill-terms.json');
  const p=st.placeholders['cc.tag.op'];
  console.log(st.terms[p.termId].name, '|', st.terms[p.termId].desc);
  console.log('涉及技能:', p.usedBy.join(' '))"

# 技能条目自包含验证：原文里的「部分设施」「外势」等弹窗释义随条目携带
node -e "const s=require('./meta/mirror/RIIC-Web/clean/building-skill-catalog.json')['control_prod_tra_spd_000'];
  console.log(s.name, '|', s.description);
  for (const r of s.termRefs) console.log(' ', r.text, '=>', r.desc)"

# 按类别标签拉技能清单（如「订单效率」类全部技能）
node -e "console.log(require('./meta/mirror/RIIC-Web/clean/skill-terms.json').tags['订单效率'])"

# 按职业筛干员（如全部近卫）
node -e "console.log(require('./meta/mirror/RIIC-Web/clean/operator-catalog.json').filter(o=>o.professionLabel==='近卫').map(o=>o.name).join('、'))"

# 全量统计某口径（如所有「精英 2 提升」的持有情况）
node -e "const t=require('./meta/mirror/RIIC-Web/clean/operator-skill-text.json');
  t.flatMap(o=>o.skills.map(s=>({op:o.name,...s}))).filter(s=>s.unlock==='精英 2 提升').length"
```
