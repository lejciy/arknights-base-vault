# 多 Agent 协作与引用规范

## 编写前

1. 查 `知识库模块设计.md` 判断模块归属。
2. 查现有文档，确认事实是否已有维护位置。
3. 选择模板和文档类型；不为未来索引预先创建复杂字段。

## 最小 front matter

新增或大幅修改的 `docs/` 正文使用：

```yaml
---
type: mechanism | skill | combination | reference | operation | strategy | layout | index
status: canonical | draft | deprecated
source: [<来源标识或 URL>]
updated: YYYY-MM-DD
---
```

- `type` 与 `status` 必填；`index` 只用于模块 `README.md` 等导航入口；`draft` 表示内容仍在校对或存在未裁决分歧，检索时不应作为权威。
- `source` 有外部依据时填写，统一用列表；PRTS 等来源链接写在 `source` 里，不另设 `prts_ref`。
- `updated` 表示内容最后更新时间；不再使用 `last_updated`、`last_reviewed`、`imported`。
- 可选字段仅 `entities`、`facilities`、`topics`，用于检索切面，不得改变既有字段含义。
- 模块3 组合文档可保留关系字段：`system_id`、`operators`、`exclusive_with`、`coexists_with`、`shortcut_id`、`related_systems`。
- 已废弃字段 `tags`、`domain`、`prts_ref`、`last_updated`、`last_reviewed`、`imported` 不再新增，存量文档按本文迁移。

## 真源、引用与迁移

- 同一事实只保留一个主要维护位置。
- 跨文档使用稳定的 Markdown 链接，优先指向事实真源。
- 组合、经验、算法文档引用技能和机制，不复制完整事实或数值表。
- 改名或迁移时保留兼容入口，或在迁移说明中登记旧路径。
- 当前不强制为所有对象建立独立 ID；只有出现稳定跨文档复用需求时再引入。

## 语料洁净

`docs/` 交付的是干净的玩家知识语料，命中任何一段都应是在回答玩法问题。

- 正文只保留当前有效的事实、机制、组合、操作与经验；时效由 front matter `updated` 承担，不写「自 xx 版本起」「某日重订」这类叙事。
- 同步/导入记录、变更纪事、已知问题与待裁决、进度与待补清单、素材台账、写作规范、脚本与 commit 说明、本地磁盘路径、协作分工都不写入正文，统一登记在 `meta/`：进度与文件清单见 `meta/内容目录与进度.md`，裁决见 `meta/决策记录.md`，写法见本文。
- 模块 `README.md` 只写职责与分区导航，不写维护内容或进度承诺。

## 派生物与未来检索

文档清单、RAG manifest、向量索引、实体索引、关系图和查询路由表均由脚本生成，不手工编辑为事实来源。`docs/` 中的 canonical 正文是未来向量化候选；每个语义块应能回溯到文件和标题。图谱关系暂通过正文中的成员、条件、替代、互斥和引用关系表达，不预设图数据库或固定跳数。

## 变更检查

提交前确认：模块归属正确、没有重复真源、来源和边界清楚、内部链接有效、未修改派生索引。事实、推导、经验和运行时结果应在措辞中明确区分。
